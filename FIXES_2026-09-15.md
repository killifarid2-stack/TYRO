# WAB-TKD — Broadcast + Tournament Fixes — 2026-09-15

Implemented in this build:

1. Public Broadcast geometry is now authored in a stable 1920×1080 design space and fitted uniformly to the actual display viewport, reducing position/scale drift between Public Display windows and 1920×1080 / 1280×720 outputs.
2. Native broadcast layers establish their real rendered base geometry when first used, so Design Studio position edits are additive to the original animation instead of being based on hard-coded pixels.
3. Design Studio/runtime automatically infer RED/BLUE/WINNER flag bindings for image layers whose layer id/name identifies the side. Winner/result flags use `winnerFlag` so a winner flag cannot accidentally resolve as RED.
4. VIDEO REPLAY now has a dedicated public "WAB-TKD · OFFICIAL REVIEW / VIDEO REPLAY / RED·BLUE · REVIEW REQUEST / WAITING FOR REFEREE DECISION" stage with the correct side camera artwork and player flag.
5. IVR verdict remains visible for 3 seconds, freezes the match clock during the verdict, then returns to the exact previous phase (LIVE fight or REST). The request cannot be overwritten by a second side during an active request.
6. WOO-SE-GIROK: full gold two-hand artwork is used for the final decision frame; judge cards are smaller; the large decision frame keeps the complete hands visible; countdown numbers receive a stronger illuminated glow.
7. REST screen: POINT GAP WATCH panel removed; giant player flag/photo area is replaced by round-by-round score information, rounds won, total points, body/head hit icons; rounds remain vertical R1/R2/R3.
8. Winner/result screen: stronger WINNER + MATCH RESULT + medal header, medal on the right, round-wins displayed RED left / BLUE right, and compact winner identity with flag/photo, name, club and country information.
9. Tournament/category match identity: a bracket/category match now uses its durable match id as the match state id. This prevents a completed match from being saved as a second random match.
10. Category continuation now passes the exact waiting match id through Admin and updates that row instead of inserting a duplicate waiting row.
11. NEXT MATCH now selects the next playable match after the current bracket slot, respects explicit weight metadata when present, and falls back to category-library waiting matches in the same tournament/weight when there is no generated bracket.
12. Completed matches remain completed in the local/cloud archive and cannot be selected again as the next playable match.
